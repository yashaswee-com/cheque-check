# Environment and secrets

Cheque Check has browser-visible build settings, server-only application credentials, Supabase Auth configuration, Edge Function secrets, and operational CLI variables. Their destinations are separate; a value existing in a local example or schema does not prove it is configured in a hosted project ([environment schema](../src/lib/env/schema.ts#L15-L124), [environment examples](../.env.example#L8-L84), [Edge example](../supabase/.env.example#L7-L28)).

## Quick setup

1. Put local Next.js values in a root `.env.local`; the example file is explicitly labeled for local use. For deployed builds, set values in the hosting platform separately for QA and production ([environment example](../.env.example#L1-L5), [deployment environment schema](../src/lib/env/schema.ts#L64-L109)).
2. Configure Supabase Auth values in the Supabase project, and worker/provider values as Supabase Edge Function secrets. Do not copy service-role, provider, or signing secrets into `NEXT_PUBLIC_*` variables ([Auth local config](../supabase/config.toml#L205-L220), [Edge example names](../supabase/.env.example#L7-L28), [server-only schemas](../src/lib/env/schema.ts#L109-L124)).
3. Keep production, QA, preview, and development destinations distinct. The public schema rejects local Supabase URLs for deployed labels; when observability is enabled, the monitoring schema rejects production telemetry settings on a preview deployment ([environment checks](../src/lib/env/schema.ts#L64-L109), [monitoring checks](../src/lib/env/schema.ts#L15-L61)).
4. Rebuild when changing `NEXT_PUBLIC_*` values because the framework embeds public settings in the client build ([Next config](../next.config.ts#L1-L25), [public environment schema](../src/lib/env/schema.ts#L64-L110)).

The full-width yellow-and-black diagonal QA strip is enabled only when `NEXT_PUBLIC_APP_ENV=qa` at build
time, including preview builds configured with that value. Set this separately
in the hosting environment and rebuild; production and development builds do
not show it. Repository configuration does not establish hosted values.

## Variable groups

- **Supabase client:** `NEXT_PUBLIC_SUPABASE_URL` and `NEXT_PUBLIC_SUPABASE_ANON_KEY` are browser-visible and required by the public schema ([schema](../src/lib/env/schema.ts#L64-L76)). RLS remains the data-access boundary ([server client](../src/lib/supabase/server.ts#L6-L24), [lifecycle policies](../supabase/migrations/20261021000000_lifecycle.sql#L36-L76)).
- **Public feature/build settings:** `NEXT_PUBLIC_APP_ENV`, `NEXT_PUBLIC_DEPLOYMENT_KIND`, `NEXT_PUBLIC_PHONE_AUTH_ENABLED`, `NEXT_PUBLIC_TURNSTILE_SITE_KEY`, `NEXT_PUBLIC_RAZORPAY_KEY_ID`, `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `NEXT_PUBLIC_WHATSAPP_SUPPORT_NUMBER`, `NEXT_PUBLIC_LOG_LEVEL`, `NEXT_PUBLIC_SENTRY_DSN`, and `NEXT_PUBLIC_CLARITY_PROJECT_ID` ([environment example](../.env.example#L14-L35)). Core settings are validated by the app schema ([public schema](../src/lib/env/schema.ts#L64-L110)). Phone auth in production requires a Turnstile site key ([conditional check](../src/lib/env/schema.ts#L97-L108)). The VAPID public key is consumed by Push but is not declared in this schema ([push service](../src/features/notifications/services/push.service.ts#L13-L57)).
- **Google Places suggestions:** `NEXT_PUBLIC_GOOGLE_MAPS_API_KEY` is optional and enables onboarding location suggestions. Enable the Places API (New) and Maps JavaScript API in Google Cloud; restrict the key to the app's website origins and those APIs. Without a key, or if the API cannot load, onboarding still accepts a plain-text location. This browser-visible key is not a secret and must be restricted.
- **Observability:** `NEXT_PUBLIC_OBSERVABILITY_ENABLED`, `NEXT_PUBLIC_PREVIEW_MONITORING_ENABLED`, `NEXT_PUBLIC_MONITORING_POLICY_APPROVED`, `NEXT_PUBLIC_CLARITY_ENABLED`, `NEXT_PUBLIC_REPLAY_ENABLED`, `NEXT_PUBLIC_APP_RELEASE`, and sampling-rate variables are build-time flags and identifiers ([schema](../src/lib/env/schema.ts#L15-L61), [environment example](../.env.example#L40-L57)). When enabled, monitoring requires app environment and release metadata; preview deployments require the explicit preview flag, and the QA environment-file expectations are checked by a test ([monitoring config](../src/lib/monitoring/config.ts#L20-L46), [QA config test](../src/lib/monitoring/config.test.ts#L25-L34)).
- **Server credentials:** `SUPABASE_SERVICE_ROLE_KEY`, `OPENAI_API_KEY`, `RAZORPAY_KEY_ID`, and `RAZORPAY_KEY_SECRET` are validated by server-only getters ([server environment](../src/lib/env/server.ts#L1-L35)). `SENTRY_AUTH_TOKEN` is a trusted build-time source-map upload credential ([Next config](../next.config.ts#L6-L25)). Never expose these to the browser ([security guidance](security-and-known-risks.md#secret-boundaries)).
- **Supabase Auth provider:** `SUPABASE_AUTH_SMS_TWILIO_AUTH_TOKEN` and `SUPABASE_AUTH_CAPTCHA_SECRET` belong in Supabase Auth, not browser variables ([Auth CAPTCHA config](../supabase/config.toml#L205-L220)). The checked-in local config disables Twilio SMS; hosted provider state is not established by that file ([local config](../supabase/config.toml#L284-L297)).
- **Edge providers:** `TWILIO_ACCOUNT_SID`, `TWILIO_AUTH_TOKEN`, `TWILIO_FROM_NUMBER`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`, and `RAZORPAY_WEBHOOK_SECRET` are Supabase Edge Function secrets ([Edge example](../supabase/.env.example#L7-L28), [dispatcher provider setup](../supabase/functions/notifications-dispatcher/index.ts#L80-L100), [webhook verification](../supabase/functions/razorpay-webhook/handler.ts#L30-L50)). Auth SMS and reminder voice are separate integration points ([local Auth Twilio setting](../supabase/config.toml#L284-L297), [dispatcher Twilio config](../supabase/functions/notifications-dispatcher/index.ts#L80-L100)).
- **Operations and tests:** `SUPABASE_DB_URL`, `SUPABASE_ACCESS_TOKEN`, `PLAYWRIGHT_BASE_URL`, and `PORT` are used by CLI and test workflows ([package scripts](../package.json#L25-L40), [E2E QA setup](../e2e/README.md#L24-L45)). A QA reset is destructive and must target the intended test project ([E2E QA setup](../e2e/README.md#L24-L45)).

The Edge Function example also defines delivery-safety controls (`NOTIFICATIONS_FORCE_RUN`, `NOTIFICATIONS_TEST_MODE`, and `NOTIFICATIONS_TEST_PHONE`); they belong with the Edge Function secrets, not the Next.js app ([Edge example](../supabase/.env.example#L21-L28)). Cron database credentials are provisioned as Supabase Vault entries named `project_url` and `service_role_key`, not as app environment variables ([app example](../.env.example#L72-L84)).

## Conditional requirements

- **Marketing:** `NEXT_PUBLIC_MARKETING_ANALYTICS_ENABLED` enables the consent UI and app ingestion; `NEXT_PUBLIC_META_PIXEL_ID` selects the browser Pixel. `MARKETING_COOKIE_SECRET` signs consent/visitor cookies; `MARKETING_TRUSTED_IP_HEADER` is optional and must identify a proxy-overwritten header. CAPI credentials, API version, test code, mode, app origin, and delivery flags belong in Supabase Edge secrets, not public settings. Database collection is separately disabled by default. Follow the [marketing setup checklist](marketing-analytics.md#setup-and-qa-checklist), including the explicit QA/live guards ([app example](../.env.example), [Edge example](../supabase/.env.example), [ingestion](../src/features/analytics/server.ts), [worker configuration](../supabase/functions/marketing-delivery/delivery.ts)).

- Phone OTP UI defaults off; production phone authentication requires the public Turnstile site key in the build ([schema](../src/lib/env/schema.ts#L75-L108)). Supabase Auth also needs its CAPTCHA secret and SMS provider configured in the hosted Auth project ([Auth configuration](../supabase/config.toml#L205-L220), [phone send flow](../src/features/auth/server/phone-auth.ts#L141-L215)).
- Sentry collection defaults off. If enabled, app environment and release are required; preview deployments also require `NEXT_PUBLIC_PREVIEW_MONITORING_ENABLED=true`. An enabled Vercel Sentry build also needs source-map upload credentials ([schema](../src/lib/env/schema.ts#L15-L61), [monitoring config](../src/lib/monitoring/config.ts#L20-L46), [Next config](../next.config.ts#L6-L25)). The test suite checks that the local QA env file includes the Sentry monitoring, preview, and policy-approval flags; that check does not establish hosted values ([QA config test](../src/lib/monitoring/config.test.ts#L25-L34)).
- The push service reads `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, while the public Zod schema shown in this checkout does not declare that key. The code therefore does not establish schema validation for this setting; verify it in each build ([public schema](../src/lib/env/schema.ts#L64-L110), [push service](../src/features/notifications/services/push.service.ts#L13-L57)).

## Deployment state {#deployment-state}

The repository contains local Supabase defaults, including disabled Twilio SMS and disabled database network restrictions; these are not evidence of hosted project settings ([local database config](../supabase/config.toml#L73-L82), [local Auth and SMS config](../supabase/config.toml#L284-L311)). Never infer deployed values, secret rotation state, hosting environment, or active provider configuration from checked-in sample files ([local example](../.env.example#L1-L5), [Edge example](../supabase/.env.example#L1-L6)).

For service topology and deployment verification see [infrastructure and deployment](infrastructure-and-deployment.md); for which settings are sensitive and why see [security and known risks](security-and-known-risks.md#secret-boundaries).
