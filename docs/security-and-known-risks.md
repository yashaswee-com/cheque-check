# Security and known risks

This page records security boundaries and repository-level deployment risks visible in the checked-in code. It is not a penetration test or a complete vulnerability scan. No scanner, test suite, or production environment was run as part of this documentation snapshot, so this page does not claim that the app is vulnerability-free or that a provider is configured ([CI checks](../.github/workflows/quality.yml#L39-L71), [documentation evidence rules](../constitution.md#L16-L41)).

## Quick security checklist

- Keep service-role, database, provider, webhook, and private VAPID credentials server-side ([server-only environment getters](../src/lib/env/server.ts#L1-L35), [secret examples](../supabase/.env.example#L7-L28)).
- Treat PostgreSQL RLS and server-side authorization as the access boundary; client UI gates are not authorization ([lifecycle policies](../supabase/migrations/20261021000000_lifecycle.sql#L36-L76), [Premium database assertion](../supabase/migrations/20261017030000_premium_workspace.sql#L22-L38)).
- Verify the webhook gateway setting, contact proxy header behavior, public route allowlist, and VAPID build config in each deployment ([deployment risks](infrastructure-and-deployment.md#deployment-verification), [contact route](../src/app/api/contact/route.ts#L47-L64), [public route policy](../src/lib/supabase/public-routes.ts#L1-L17)).
- Do not describe the application PIN or privacy cover as encryption or screenshot prevention ([PIN gate](../src/features/security/components/pin-gate.tsx#L17-L55), [privacy cover](../src/features/security/components/privacy-shield.tsx#L10-L86)).

## Access boundaries

Supabase Auth supplies the user session. User-facing repositories use session-scoped clients, while a separate server-only admin client uses service-role access ([server client](../src/lib/supabase/server.ts#L6-L24), [admin client](../src/lib/supabase/admin.ts#L1-L12)). Database migrations enforce active-owner/business checks and restrictive row policies; application pages alone are not the authorization control ([lifecycle policies](../supabase/migrations/20261021000000_lifecycle.sql#L36-L149)).

Private storage access checks the authenticated owner and active record reference before issuing a short-lived URL ([storage route](../src/app/api/storage/%5Bbucket%5D/%5B...path%5D/route.ts#L14-L61), [reference checks](../supabase/migrations/20261021000000_lifecycle.sql#L420-L443)). Public contact uses a service-only RPC and rate-limits address hashes; a proxy that forwards caller-controlled address headers can undermine the intended per-address limit ([contact route](../src/app/api/contact/route.ts#L47-L105), [rate-limit RPC](../supabase/migrations/20261107000000_shared_contact_rate_limits.sql#L1-L57)).

## Secret boundaries {#secret-boundaries}

`NEXT_PUBLIC_*` values are shipped to the browser and must not contain credentials. The app validates service-role, OpenAI, and Razorpay server credentials in a `server-only` module ([server environment getters](../src/lib/env/server.ts#L1-L35), [public schema](../src/lib/env/schema.ts#L64-L124)). Edge Function secrets belong in Supabase's function environment, while Auth SMS credentials belong in the Auth provider configuration ([environment destinations](environment-and-secrets.md#L21-L34)).

## PIN and privacy limits

The application PIN uses PBKDF2-HMAC-SHA256 with a random salt and 600,000 iterations; server RPCs protect mutation and attempt accounting ([PIN derivation](../src/features/security/server/crypto.ts#L1-L18), [PIN database controls](../supabase/migrations/20261106010000_application_pin.sql#L1-L65)). The PIN gate is an additional application UI/session lock; a person controlling the browser or a valid Auth token can bypass client-only UI. It is not at-rest encryption, offline protection, or protection against browser compromise ([PIN gate](../src/features/security/components/pin-gate.tsx#L17-L55), [PIN handler](../src/features/security/server/handler.ts#L21-L120)).

The privacy cover responds to browser focus/visibility and delivered keyboard events; it cannot reliably prevent operating-system captures, external cameras, or hardware screenshot buttons ([privacy shield](../src/features/security/components/privacy-shield.tsx#L10-L86), [privacy test limits](../src/features/security/privacy.test.tsx#L39-L66)).

| Image optimization hostname       | `next.config.ts` contains a configured Supabase image hostname; alternate project hostnames may not be optimized unless configuration is updated ([image host config](../next.config.ts#L32-L54)).                                                                                                                                | Deployment-specific.                                                                                        |
